Services, in detail.

Six kinds of engagement. For each one: what it covers, what you actually receive, and the stack it is usually built on. Every engagement ends the same way — a system that is yours, documented, with no lock-in.

Custom web applications

Off-the-shelf software makes your business fit the tool. A custom application does the opposite: it is designed around how your company actually works — your approval steps, your reports, your exceptions. I design and build these systems end to end, from the database to the screens your staff touch all day.

What’s included

  • Process analysis — we map how work flows today before writing code
  • System design document you approve before building starts
  • Admin dashboard with the reports your business runs on
  • Multi-user roles and permissions, down to module level
  • Automations for the repetitive steps that eat staff hours
  • Deployment, staff training and written documentation

What you receive

  • Deployed, working system — not a demo
  • Full source code, yours without lock-in
  • Documentation and one handover session
  • Support window after launch for fixes

Typical stack — Laravel / PHP · Node.js · React / Next.js · MySQL / PostgreSQL

ERP & management systems

When sales live in one notebook, stock in another and staff records in a spreadsheet, the business runs on memory. An ERP replaces that with one system of record: every module reads the same data, so the number the owner sees is the number the counter charged.

What’s included

  • Sales, inventory, staff, customers and accounts modules
  • Built on proven foundations (Frappe / ERPNext) or custom-built where that fits better
  • Dashboard reporting the owner actually reads
  • Help migrating your existing data in
  • Backup setup so the system can be restored, not rebuilt
  • Role-based access for managers, cashiers and staff

What you receive

  • Deployed ERP with your real data inside
  • Admin and staff training
  • Documentation for day-to-day operations
  • The system runs on your server, under your control

Typical stack — Frappe / ERPNext · Python · MariaDB · Custom Laravel builds

POS platforms

A point-of-sale system has one unforgiving requirement: it cannot stop. The POS platforms I build are designed around the worst moment — the internet drops mid-rush and the counter still has to bill. They run in production today in restaurants and retail.

What’s included

  • Fast billing flow designed for the person at the counter
  • Offline selling with automatic sync when the connection returns
  • Web POS and Windows desktop POS on one shared backend
  • Catalog, discounts and offers managed centrally
  • Shifts, payments and end-of-day reporting
  • Role-based staff access on every selling surface

What you receive

  • Installed POS, configured with your catalog
  • Counter staff training
  • Sync and backup verified before go-live
  • Documentation for daily open/close routines

Typical stack — Tauri (Windows desktop) · Web POS · ERP integration · Local-first data
